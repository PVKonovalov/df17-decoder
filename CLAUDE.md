## Common requirements

- After implementation, write down in RELEASE.md file what was implemented in the format "Date: Implementation
  Description" (< 200 characters)
- When changing an API (a REST endpoint's path/params, or a request/response shape), find and check every caller of it —
  both backend (other handlers/services) and frontend — and update them too.

- Don't use a lot of code comments. For function describe arguments and results. The best comments is a code.

## Project

Go project for a Mode S / ADS-B decoder (see README). It covers DF17/18 decoding (callsign, altitude, CPR position, velocity, status), Mode S altitude and squawk for non-ADS-B aircraft, an aircraft state table, a JSON/WebSocket API, and a React web UI (map and table) embedded in the single binary.

The full spec and milestone plan are in `AGENT_PROMPT.md` (backend) and `FRONTEND_PROMPT.md` (web UI). Consume raw frames only (AVR/Beast); no dump1090 decoded outputs, no third-party ADS-B libraries. The backend is stdlib only, apart from `gopkg.in/yaml.v3`, `github.com/gorilla/websocket` (approved for `/api/ws`) and `modernc.org/sqlite` (approved for the flight history: pure Go, no cgo, so `make dist` and the distroless image stay static). `github.com/gin-gonic/gin` is approved if needed but not used, because the stdlib `ServeMux` covers the routing. Frontend dependencies are limited to the list in `FRONTEND_PROMPT.md` (`echarts` is approved for the Statistics page); ask before adding others.

**Progress:** All backend milestones 1–7 are done (decoding of DF17/18 and Mode S replies, aircraft tracker, HTTP/JSON API with SSE and stats, Beast input with RSSI, README). Web UI (`FRONTEND_PROMPT.md`): all milestones 1–5 are done (backend endpoints and embed, scaffold, map, table and selection, polish with busy replay and README). Map tiles are configurable (`map` config section) and default to public OpenStreetMap, which needs no API key. Track buffer and SQLite flight history (`HISTORY_PROMPT.md`): milestones 1–5 are done. Tape recorder and playback (`PLAYBACK_PROMPT.md`): milestones 1–5 are done. Statistics page (`STATS_PROMPT.md`): milestones 1–5 are done.

## Architecture

Data flow: `source.Source.Run` → `chan source.Frame` → `tape.Recorder.Record` (non-blocking) and `app.Service.handle` (decode, count errors) → `tracker.Tracker.Update` (known-address filter, CPR, state, change logging, trails, flights → optional `history.Store`) → `api` handlers read `Tracker.Snapshot()`/`Get()`/`TrailPointsSince()` copies and `stats.Stats`.

`app.Service`: `Ingest(ctx)` consumes the source until it ends; integration tests call it directly. `Run(ctx)` adds the HTTP server and a 1 s expiry ticker, and keeps serving after a file replay ends. HTTP request contexts derive from the service ctx (`BaseContext`), so SSE and WebSocket streams end on shutdown. `Listen()` can be called first to learn the bound address (tests use `127.0.0.1:0`). With `history.enabled`, `New` opens the store (its `LastFlightID` seeds the tracker), `Run` runs its writer on a context that outlives the HTTP server, and on shutdown calls `Tracker.SyncFlights()` (live source; else `CloseFlights()`), then stops the writer (final flush) and closes the store.

Address/parity rule: `modes.Decode` sets `Message.AddressParity` for DF0/4/5/16/20/21 and puts the CRC remainder in `ICAO`. The tracker accepts those only if `KnownAddresses` has seen the address in an intact (not bit-repaired) DF11/17/18 frame within `tracker.knownAddressTTL`. DF11 is accepted when its remainder is ≤ 0x7F (interrogator code).

- `internal/config`: `trails` (`window`, `minInterval`), `history` (`enabled`, `file`, `flushInterval`, `flightGap`, `retention`), `tape` (`enabled` true by default, `dir`, `segment` dividing a day, `flushInterval` < segment, `retention`, `minFreeMB`; the dir or its parent must be writable) and `playback` (`maxSessions`, 0 disables; `idleTimeout`) and `stats` (`retention` of the rollups, default 8760h, 0 forever) sections; `source.url` also takes `tape://<dir>?from=&speed=` (`tape.ParseURL`); with history enabled, the `history.file` directory must be writable (`checkWritableDir`, exit 2). Defaults < YAML (`KnownFields(true)`) < CLI flags (`-config`, `-log-level` only). `Load` validates and reports all errors together. `config.Duration` is a YAML duration string. `Source.Endpoint()` splits `source.url` into scheme and address. The `map` section is validated at load: `tileUrl` must be http(s) and contain {z}/{x}/{y}, and `maxZoom` must be 1–22. `config/config.example.yaml` must equal `Default()`; a test enforces this.
- `internal/modes`: pure, with no I/O and no global state. `Decode(msg, time, Options)` returns a `Message` and always sets DF, even on error, so callers can count drops. All bit access goes through `bits(msg, start, length)`, which uses 1-based, MSB-first numbering matching mode-s.org. `Remainder` is the CRC-24 syndrome: 0 for DF17/18, the IC for DF11, the ICAO address for address/parity DFs. Each decoder cites its mode-s.org section in a one-line comment.
- `internal/modes` also holds velocity (TC 19), aircraft status (TC 28 subtype 1, `Squawk` for 13-bit identity fields) and operational status (TC 31). Section citations point to https://mode-s.org/1090mhz/content/... (the old /decode/ path redirects). Tests build synthetic ES frames with valid parity via `makeES`/`me` in `status_test.go`.
- `internal/modes/surveillance.go`: DF11 (`AllCall`) and address/parity replies (`Surveillance`: AC altitude, ID squawk, FS/VS on-ground, alert/SPI, BDS 2,0 callsign when MB starts with 0x20). Test helper `makeAP` builds frames whose remainder equals a given address.
- `internal/modes` also holds altitude (`Altitude12` for ES, `Altitude13` for the AC field, `Gillham`) and CPR (`NL`, `CPRGlobal`, `CPRLocal`, and `EncodeCPR` for building synthetic test frames).
- `internal/modes/target.go`: TC 29 subtype 1 (`TargetState`: selected altitude with MCP/FMS source, baro setting, selected heading, `AutopilotModes` when the mode status bit is set); subtype 0 returns `ErrUnsupportedTC`. The tracker stores them as `selectedAlt`, `selectedAltSource`, `selectedHeading`, `baroSetting` and `autopilotModes` (a slice, cloned in `Aircraft.clone()`), shown in the UI detail panel.
- `internal/modes/commb.go`: Comm-B inference for DF20/21 MB fields that aren't BDS 2,0. `decodeBDS40/50/60` check status-bit consistency, reserved bits and value ranges; 6,0 also checks IAS against Mach at the reply's AC altitude (`CASToMach`, ISA). `Surveillance.CommB` holds every register that fits, with `Ambiguous` set when several do. The tracker (`updateCommB`) applies an ambiguous reply only when exactly one candidate agrees with fresh (≤30 s) ADS-B velocity or the previous accepted Comm-B report, and rejects 5,0/6,0 reports that contradict it (GS/IAS > 30 kt, track/heading > 20°, opposite vertical rates both over 1000 ft/min). While ADS-B velocity is fresh it owns GS, track and vertical rate. The counters are `commBAmbiguous` and `commBRejected` in stats; the new aircraft fields are `roll` and `mach`.
- `internal/modes/surface.go`: TC 5–8 (`SurfacePosition`: `Movement` ground speed, track when its status bit is set, CPR frame) and sets `OnGround`. Surface CPR uses 90° zones, so it is decoded only locally (`CPRSurfaceLocal`, unambiguous within 45 NM of the reference); `EncodeSurfaceCPR` builds test frames.
- `internal/source`: `TCP` (reconnects with exponential backoff, closes the conn via `context.AfterFunc` on cancel) and `File`. In file replay, `Frame.Time` is capture time derived from the `@` 12 MHz timestamps at any `replaySpeed`, so CPR pair ages and speed checks see the original timing; `*` lines reuse the last timestamped time. Both share `readAVR` and atomic `Stats`. `beast://` is a `TCP` with `Format: Beast`, read by `readBeast`. That reader unescapes doubled 0x1A, skips Mode A/C (`'1'`) and status (`'4'`) frames, counts each resync run or truncated frame as one malformed, and sets `Frame.RSSI` to `20·log10(sig/255)` dBFS (nil when the signal byte is 0). `File` detects Beast by a leading 0x1A and replays it with `readBeast` and the same replay clock (pacing and capture time from the 12 MHz timestamps, RSSI kept); live TCP passes a nil clock.
- `internal/tracker`: `PositionResolver.Resolve` tries a global decode (fresh even/odd pair), then a local decode against the aircraft's last position (younger than `tracker.ttl`), then a local decode against the receiver (≤180 NM). It rejects results beyond `maxRangeNm` or implying more than 1500 kt. A rejected global fix clears the last position so one bad fix can't lock the aircraft out. `ResolveSurface` decodes surface frames against the aircraft's recent position, else the receiver (≤45 NM), with the same checks; surface frames never enter the airborne even/odd pair.
- `internal/tracker/trail.go`, `flight.go`: `TrackPoint` (plain values; `AltSrc` and `Known` flags instead of pointers; custom compact JSON) is added in `updatePosition` after the range/speed checks, thinned (first point per fixed `trails.minInterval` slot of unix time, so a tracker started later converges with the live one, `trailTurnDeg` 3°, `trailAltFt` 200 ft, on-ground change) and trimmed to `trails.window` of data time before the newest point. Trails live on the `flight`, kept in `Tracker.flights` separately from `aircraft`: a flight opens on the first accepted message, continues while heard within `ttl + history.flightGap`, and closes in `Expire` after the gap, on a different non-empty callsign (the live trail carries over), or via `CloseFlights` on shutdown. Mode-S-only aircraft get `Sample`s (alt ±100 ft, squawk change, 30 s; same time replaces). Events go to `Options.Flights` (`FlightSink`, called under the lock, must not block); IDs continue after `Options.LastFlightID`. `TrailPointsSince(sent)` returns only points newer than a caller-owned per-ICAO map and forgets aircraft no longer live.
- `internal/tape`: `Recorder` writes every frame (time, 12 MHz timestamp, signal byte, data; `format.go`) to gzip segments `<dir>/YYYY/MM/DD/<UTC start>.tape.gz`, the active one as `.part` (renamed on close, finalized at start), flushed every `flushInterval` (`LastFlush` moves on every successful tick, also with nothing new, so a quiet sky isn't a stale writer), fsynced on close. One goroutine (`Run`) owns the files; `Record` drops and counts when the queue is full. Hourly retention by segment boundary; the disk guard (`FreeSpace` injectable) deletes the oldest segments, then pauses. `Tape` (`reader.go`) reads it back: `Seek(t)` returns a `Reader` across segments (including the flushed part of `.part`) whose `Next` reports gaps over `GapThreshold` (60 s); `Extent` lists spans (cached per finished segment, UTC). `Source` is the `tape://` input.
- `internal/playback`: `Pipeline` is a decoder + own `tracker.Tracker` with no flight sink, coverage or live stats, aged by a virtual `Clock` (`tracker.Options.Clock`; paused = frozen, speed-scaled). `Rebuild(t)` decodes from `t − Preroll` (`max(trails.window, ttl) + 1m`); `TestRebuildMatchesLive` checks the result equals a live pipeline at several T. `Manager.Start` opens a `Session` (limit `MaxSessions`, range check against `Bounds` and now) whose goroutine paces frames by the clock, jumps silences over 60 s (`Gap`, `GapSeq`), frees its tracker after `IdleTimeout` paused (play re-seeks), and ends (`Ended`) within `EndMargin` of now. `Status.Seq` counts seeks so the WebSocket sends full trails after each.
- `internal/history`: SQLite via `modernc.org/sqlite`. One writer connection (WAL, `synchronous=NORMAL`, busy timeout, `auto_vacuum=INCREMENTAL`) owned by `Store.Run`; HTTP reads use separate `mode=ro` connections. The sink methods enqueue into a bounded channel and drop+count when full. `Run` writes everything queued every `flushInterval` in one transaction (flight upsert, `INSERT OR IGNORE` positions, `INSERT OR REPLACE` samples, per-flight `points`/`last_seen`/`max_alt` aggregates), flushes on cancel, and deletes closed flights older than `retention` hourly, then `incremental_vacuum`. `schema.go` holds numbered `migrations` with the version in `meta` (v2 dropped `flights.country`: it is derived from the ICAO address on read). `Open` closes open flights last seen before `ResumeWithin` (tracker.ttl + flightGap for live tcp/beast sources, else 0: all) and loads the rest with their stored trail (`ResumeTrail`) as `ResumeFlights()` for `tracker.Options.Resume`; on shutdown the app calls `Tracker.SyncFlights()` (live) instead of `CloseFlights()`, so a restart continues flights. `read.go`: `Flights` (`Text`: ICAO or callsign prefix), `FlightByID`, `At` (per flight, last position and sample in `[t-ttl, t]`). `timeline.go`: `Timeline` counts flights active per bucket (`[ADS-B, Mode-S]`, at most 2000 buckets) and emergency events (first Mode-S sample with 7500/7600/7700, or the ADS-B flight's first sighting). Retention and `/api/history/at` use data time stored as unix ms, retention compares it with the wall clock.
- `internal/history/rollup.go`, `stats.go`: schema v3 tables `hourly` (keyed by unix seconds), `hourly_country`, `hourly_operator`; v4 adds the receiver columns (`frames`, `crc_failures`, `fixed_bit_errors`, `cpr_rejected`, `reconnects`, `silent_minutes`, `signal_dbfs`), `rollup_version`, `hourly_altitude` (band: `BandGround` −1, `BandUnknown` −2, else the 5000 ft lower bound, capped at 40000), `aircraft_seen` (first/last sighting per ICAO, filled from flights by the migration, outlives flight retention) and `notable_events` (`emergency`/`firstSeen`, PK kind+icao+flight+squawk, `INSERT OR IGNORE`). An address is first seen when its earliest stored flight starts in the hour and `aircraft_seen` has nothing earlier, so backfill order doesn't matter; emergencies are ADS-B flights with an emergency squawk (at `first_seen`) and Mode-S samples (first in the hour). The hourly row is an upsert: computed columns replaced, live columns and sizes `coalesce`d, so reruns without live data keep them; the backfill also recomputes hours with `rollup_version` < `rollupVersion` but never hours reaching past `history.retention`. `liveSnapshots` (begin/boundary/minute; `part`, `hour`, `since`, `unsaved`) holds `Counters` at boundaries and at the run's start, plus `carry`: parts of hours saved on shutdown to `live_partial` (schema v5, `saveLive`; `loadLive` reads and deletes them at start, so a crash leaves the hour unknown), continued by the next run with the downtime counted as silent; it holds `Counters` (from `app.rollupSources`, incl. `stats.AddSignal` linear power) at boundaries and counts silent minutes from a per-minute frame sample. `RunRollups` (started next to `Run` on the same context) snapshots the counters at each HH:00, rolls up the previous hour at HH:05 through the writer connection (upsert, idempotent), samples db (+wal/shm) and tape sizes, backfills missing hours in the background (NULL messages and sizes, not before `stats.retention`) and prunes daily. `computeHour` counts distinct ICAO addresses of flights overlapping the hour (ADS-B if any flight in the hour is), countries via `tracker.Country`, `OperatorPrefix` (`^[A-Z]{3}[0-9]`), and max range/bearing from `positions` against `Options.Receiver`. Messages and the receiver counters are known only when both boundary snapshots exist (`liveSnapshots`). Reads (`Hourly`, `Countries`, `Operators` as aircraft-hours, `RangeDaily` per local day, `AltitudeBands`, `NotableEvents`, `SizeSamples`, `Oldest`) use `s.ro` and append the current hour computed live (`partial`, cached 30 s).
- `internal/storage`: `Reporter` builds `GET /api/storage` (cached 60 s) from `Sources`: `Statfs` (linux/darwin, injectable `Volume`), the tape (`Stats().GuardDeleted`, `Tape.BytesSince` fallback growth), the history (`SizeSamples`). Growth sums only increases of consecutive samples (≥ 1 h span); steady state = growth × retention; `daysUntilFull` counts retention-0 growth, `daysUntilGuard` everything below its steady state; `warning` below 2 × `tape.minFreeMB`. The state dir is the working directory.
- `internal/tracker/tracker.go`: the aircraft table. One writer (`Update`), many readers (`Snapshot`/`Get`/`Len`) behind an RWMutex. Readers get copies via `Aircraft.clone()`. `rssi` is the average of the last 8 frames' signal (linear power, `entry.addSignal`). Pointer fields in `Aircraft` must be replaced, never mutated in place, because clones share them. Ages use data time: newest frame time plus wall time since it arrived, so fast replays expire correctly. `country.go` maps ICAO blocks to states (full Annex 10 Table 9-1, cross-checked with tar1090/dump1090; ICAO's own blocks omitted) by binary search, with `countrySubBlocks` (UK territories, Hong Kong) winning over their state's block.
- `internal/api`: Go 1.22 `ServeMux` patterns. JSON is camelCase, with unknown values omitted via pointers and `omitempty` (a real 0 ft stays). Unknown `/api/*` paths return a JSON 404. `/api/stream` is SSE (`data: <aircraft array>`). `/healthz` returns 200 while frames arrive or the source stays connected after its first frame (`idle`, a quiet sky), 503 before the first frame or when disconnected and silent. `/api/stats` carries `serverTime`; the UI measures ages against it. `/api/receiver` returns the configured receiver position, `/api/map` the tile layer (`config.Map`: `tileUrl` with {z}/{x}/{y}, attribution, maxZoom, darkFilter). `/api/ws` (`ws.go`, gorilla) is the UI's only channel: `{type,data}` JSON with `receiver`, `map` and `trails` (`{window, trails}`) once, then `trailPoints` (per connection, only unsent points), `aircraft` and `stats` every `StreamInterval` (shared builders `aircraftByICAO`/`statsSnapshot` with SSE and `/api/stats`). It is same-origin only, pings every 30 s, and closes with 1001 when the service ctx ends. The frontend must not poll. Client messages on `/api/ws` are `{type:"playback", data:{action, t?, speed?, seconds?}}` (`parseControl`; invalid ones get `{type:"error"}`, the connection stays): `seek`/`step` from live start a `Deps.Playback` session, `live` closes it; in playback `trails`/`trailPoints`/`aircraft` come from the session (full `trails` when `Status.Seq` changes), `stats` stays live, and every update ends with `playback` (`wsPlayback`) when playback is enabled. `/api/tape/extent` serves `Deps.TapeData`. `statspage.go`: `/api/storage` (`Deps.Storage`) and `/api/stats/hourly|countries|operators|range-daily|altitude|notable` (`from`/`to` default 24 h, clamped to `stats.retention`, at most 400 days; `limit` 1–500, notable default 100; `tz` an IANA name, `Local` refused, `time/tzdata` embedded), 503 without history; `TestStatsContract` checks nested keys against `web/src/api/stats.fixture.json`. `/api/history/flights`, `/api/history/flights/{id}`, `/api/history/at?t=` and `/api/history/timeline` (`history.go`) serve `Deps.History` and return 503 when it is nil; `/api/stats` adds `history*` fields only when it is set. `TestTrackPointContract` checks `TrackPoint` JSON against `web/src/api/trackpoint.fixture.json`. Every other path (`/`) serves `Deps.UI`, the `web.Dist()` embed of `web/dist`; GET paths that aren't files fall back to `index.html`. Hashed `assets/` get an immutable cache header. `ui_test.go` `TestAircraftContract` reflects a fully populated `tracker.Aircraft` and compares its JSON keys with `web/src/api/aircraft.fixture.json`, so a new `Aircraft` field requires updating the fixture and the TS types.
- `internal/coverage`: range outline, 180 buckets of 2°, keeping the furthest accepted position per bucket (distance, point, altitude, data time), and a polar grid (2° × 5 NM cells per altitude band low/mid/high/unknown) of position counts and signal (linear-power average, min, max dBFS), served compactly as `Cell` arrays by `GET /api/coverage/grid` and pushed as `coverageGrid` on `/api/ws` every `Deps.GridInterval` (60 s). The tracker feeds it through `Options.Coverage` (a `CoverageRecorder` interface) only after the range and speed checks. `Save` writes JSON atomically and only when changed; `Load` ignores a file saved for another receiver position (±0.001°) or bucket width. `app.Service` loads `coverage.file` at start, saves every minute and on shutdown, and serves `GET /api/coverage`; `/api/ws` pushes `coverage` on connect and every `Deps.CoverageInterval` (10 s). Config validation creates and removes a temp file in the `coverage.file` directory, so an unwritable path is a load error (exit 2); `saveCoverage` warns once per failure streak and logs recovery. The systemd unit has `StateDirectory=df17-decoder` and `WorkingDirectory=%S/df17-decoder`, so a relative `coverage.file` lands there; the Docker image has a nonroot-writable `/var/lib/df17-decoder`, which is also its working directory, so relative `tape.dir`, `history.file` and `coverage.file` land on the volume.
- `internal/stats`: atomic counters, per-DF frames, and messages/s over a 60 s window of wall-clock buckets.
- `internal/geo`: haversine distance (NM) and initial bearing.
- `internal/app`: wiring and the decode loop. `cmd/df17-decoder/main.go` stays thin (flags `-config`, `-log-level`, `-version`).
- `internal/version`: `Get()` returns the version and commit set by `make` via `-ldflags -X` (from `git describe --tags --always --dirty`), otherwise from `debug.ReadBuildInfo` (module version, or `dev-<rev>[-dirty]`), otherwise `dev`. It is logged at startup and reported as `version` in `/api/stats` (`Deps.Version`), and the UI header shows it next to the title.
- Deployment: `make dist` writes static linux/arm64, arm (GOARM=7) and amd64 binaries to the gitignored `dist/`. `deploy/df17-decoder.service` is a hardened systemd unit (DynamicUser, no restart on exit code 2). The `Dockerfile` has three stages (node:26 UI, golang:1.26 static build with VERSION/COMMIT build args, distroless nonroot) and reads its config from `/etc/df17-decoder/config.yaml`; `make docker` passes the version, since `.git` is in `.dockerignore`.
- `cmd/replaygen`: synthetic capture generator (AVR text, or Beast with `-format beast`: signal byte from distance, -3 dBFS at ≤5 NM falling 20 dB/decade plus noise, clamped at -40) with its own frame encoders (ES TC 4/6/11/19/28/29, DF4/5/11, DF20 Comm-B 4,0/5,0/6,0 for half of the Mode-S-only aircraft), including one 7700 aircraft; ADS-B aircraft draw an emitter category from `categories` (A3 55%, A5, A2, A1, A4, A7, A6, B1/B2/B6; `lowAndSlow` ones fly low and slow with `registration` callsigns), one in three taxiing aircraft is a C2 vehicle; `-taxiing` (6) adds aircraft taxiing at an airfield 6 NM north-east of the receiver (TC 6 surface positions, CA 4); `main_test.go` round-trips them through `modes.Decode`. `-arrivals` (0.4) and `-departures` (0.3) set the share of aircraft that start mid-capture (ADS-B ones at the coverage edge, heading inward) or stop early. `-config` takes the receiver lat/lon (and caps the range at 0.9 × `maxRangeNm`) from a service config, with explicit flags winning. `make busy` passes `config/demo.yaml` and `-format beast` and writes the gitignored `testdata/busy.bin` (150 aircraft, 10 min, about 5 MB), and `make demo` replays it with `config/demo.yaml` (port 8080).
- `web`: `embed.go` embeds `web/dist`. `vite build` writes `web/dist/app` (gitignored); `Dist()` serves it when present, otherwise the committed placeholder `web/dist/index.html`, so `go build` works without Node and builds never touch tracked files.
- `web/src` (React 19, TS 6.0 strict, because typescript-eslint doesn't support TS 7 yet):
  - `api/types.ts` mirrors the Go JSON by hand. `aircraftKeys` `satisfies Record<keyof Aircraft, true>`, and `contract.test.ts` compares it with the shared fixture.
  - `api/live.ts` `connectLive` is the only data path: `/api/ws`, reconnecting with backoff from 1 s to 30 s, and shown as "down" after 3 failures. `toAction` ignores unknown or malformed message types.
  - `state/reducer.ts` holds all state: receiver, map config, stats, aircraft (`Map` by ICAO), trails (from the server: `trails` replaces them, `trailPoints` appends via `appendTrail`, trimmed to the server's `trailWindowMs` of data time before the newest point; a snapshot drops trails of gone aircraft), and the selection, which is cleared when the aircraft disappears. `live.ts` `parseDuration` reads the Go duration string of the window. `panSeq` counts pan requests.
  - `map/style.ts` holds the pure helpers: altitude color scale 0–40k ft, signal color scale (`signalColor`, -36…-3 dBFS, red→green; `markerColor` by `ColorMode`), labels, staleness in data time, and trail segments by 500 ft color bucket. `AircraftLayer` manages Leaflet markers and trails imperatively. `map/icons.ts` holds the aircraft icons (own 24 × 24 SVG shapes, `iconFor(category)`: A1/B4 light, A2 small, A3/A4 large, A5 heavy at 30 px, A6 fast, A7 rotor, B1 glider, B2 balloon (not rotated), B6 drone, C1/C2 vehicle, else generic; `categoryText` for the detail panel); a marker swaps its SVG only when its kind changes. `AircraftIcon` is the same icon for the table's first column; `App` owns the color mode (`useColorMode`, signal only when some aircraft has `rssi`) and passes it to `LiveMap` and `AircraftTable`, so both color alike. The legend lists the kinds on the map. Markers are created once and updated in place, with style writes only on change. Trails are redrawn on a canvas renderer only when the trail array identity or the stale/selected state changes. A newly created marker of a new aircraft (`newAgeMs`) gets the `pulse` class (amber ring, 3×1 s). Rings and the receiver are styled via CSS classes, because Leaflet SVG attributes don't take `var()`. `LiveMap` waits for both `receiver` and `map`. `MapLegend` shows the active scale, with an Altitude/Signal switch only when some aircraft has `rssi`; the choice is in localStorage (`map/prefs.ts`, `df17.colorMode`), and trails stay altitude-colored; tiles come from config, and the `.tiles-dark-filter` CSS inverts them in dark mode only when `map.darkFilter` is set. `CoverageLayer` draws `state.coverage` as one polygon (`map/coverage.ts` helpers: vertices, bucket under the cursor for the hover tooltip). `HeatmapLayer` draws `state.coverageGrid` as non-interactive canvas wedges, with the tooltip driven by map `mousemove` (`map/heatmap.ts`: band merge weighted by linear power, wedge geometry, `cellAt`, labels, log count colors). The legend's Coverage switch (Off/Outline/Signal/Count, Signal only when the grid has signal levels) and the heatmap band are remembered by `map/prefs.ts` (`useStored`, `df17.coverage`, `df17.heatBand`). A table click dispatches `select` with `pan: hasPosition`, and `PanToSelection` pans on a new `panSeq`. Marker clicks don't pan.

## Legacy support packages (unused by the service)

- `pkg/configuration` — loads config into a struct from a YAML file, then overrides fields from env. Precedence: YAML < dotenv file (`EnvFile`, default `.env`, missing file ignored) < process environment. Only fields tagged `env:"true"` are overridable. The env var name is `EnvVarPrefix` + the upper-cased `yaml` tag names of the enclosing structs and the field joined by `_` (e.g. `api.port` → `<PREFIX>API_PORT`). Supported kinds: string, bool (`true`/`1`/`y`), int/int32/int64, `[]string` (comma-separated). `ListEnv` lists all overridable variable names. `EnvVarPrefix`, `EnvFile`, and `ReadFromFile` are package-level vars — tests swap them and restore with `t.Cleanup`.
- `pkg/llog` — leveled logger (error/warn/info/debug/trace) wrapping stdlib `log`; global `llog.Logger`, default level info. Info/debug/trace/warn go to stdout, errors to stderr in ANSI red.

Both packages carry their own MIT `LICENSE` and a license header comment in each source file; keep that header on new files in these packages.
